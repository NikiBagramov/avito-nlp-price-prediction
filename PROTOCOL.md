# Протокол до первого обучения и просмотра результатов на test

Дата фиксации: 13 ноября 2026. Авторы команды: Никита Баграмов, Альфия Исхакова. Фактические обязанности уточняются; автоматически выполненную работу нельзя приписывать как самостоятельную работу участников.

## Исследовательский вопрос

Помогают ли русскоязычные описания объявлений прогнозировать запрашиваемую цену сверх базовых структурированных характеристик? Чем различаются частотное представление, современный многоязычный эмбеддинг и интерпретируемые признаки, извлечённые открытой LLM?

Основная задача: регрессия log(price). NLP: представление текста и извлечение семантических атрибутов; объяснение измеряет предиктивные ассоциации, не причинность. Истинные рыночные цены и суммы сделок неизвестны.

## Выборка и защита от утечек

- Публичный Kaggle-датасет; только положительные цена/площадь, доступный ID и текст от 80 символов. Повтор ID удаляется. Ценовые квантили не обрезаются.
- Предобработка NFKC, смешанные латинско-кириллические омоглифы, удаление денег, точного target и телефонов. Удаление цены не может гарантировать отсутствие всех косвенных подсказок.
- Связные компоненты общих нормализованных адресов или одинаковых текстовых шаблонов без цифр целиком попадают в один split. Групповое разделение примерно 70/15/15, seed 42/43. Это проверка переноса на не встречавшиеся адреса/шаблоны, не временной прогноз.
- split фиксируется в artifacts/splits.csv до обучения. Словарь, регрессоры, подбор гиперпараметров и retrieval используют только train; выбор варианта только dev. Сравнение на test выполняется после выбора.
- Полная выборка для недорогих подходов и эмбеддингов. Отдельное сравнение на фиксированной подвыборке 1400 train / 300 dev / 400 test для генеративной LLM; все методы этого сравнения переобучаются на одинаковых 1400 train.

## Сравниваемые методы

1. Константа: медиана log(price) на train.
2. Табличный CatBoost: площадь, комнаты, этаж/этажность, кухня, жилая, год, потолки, метро, район, тип дома и город; без точного адреса/ID и текста.
3. TF-IDF слов/биграмм + Ridge (идея текстовых AVM Zhang et al.; реализация собственная).
4. Таблица + прогноз TF-IDF в residual-модели; остатки для train получают cross-fitting по группам.
5. Qwen3-Embedding-0.6B + Ridge и таблица + эмбеддинги через Ridge на остатках, полученных cross-fitting по группам.
6. Таблица + словарные атрибуты: ремонт, мебель, вид на воду, срочность и др.
7. Таблица + извлечённые Qwen3-1.7B атрибуты. Прямые zero-shot/few-shot предсказания цены на подвыборке как адаптация Geerts et al.; few-shot примеры только train.

Обязательный сильный контроль: CatBoost с дополнительными исходными полями ремонта/мебели/отделки. Выигрыш над урезанной таблицей не означает выигрыш над всеми доступными характеристиками.

## Оценка

Основная метрика MAE(log price); вторичные MAE в рублях, RMSE, R², median APE. Гиперпараметры Ridge alpha = 1, 10, 100; CatBoost depth 6/8, iterations до 1500, early stopping 100 по dev, loss RMSE(log price), CPU 4 потока, seeds 42/43/44 для итоговых табличных вариантов. Эмбеддинги заморожены, max_length=512, normalized last-token pooling по model card. Генерация greedy, thinking off, max_new_tokens=256 для атрибутов и 32 для цены. Недействительный ответ не превращается в успех; частота ошибок и явный train-median fallback для прямого прогноза публикуются отдельно.

Парный bootstrap по группам test, 1000 повторов, 95% CI разности MAE(log price). Доверительные интервалы условны на данном разделении; они не доказывают перенос на другие города и годы. Срезы: цена, район, длина текста, наличие ремонта. Важности: SHAP CatBoost и исключение групп признаков. Анализ ошибочных объявлений и извлечённых фраз.

## Ограничения и честность

Нет независимой ручной эталонной разметки атрибутов. Сравнение с исходными полями является серебряной, неполной проверкой: поля могут отсутствовать или противоречить тексту. Автоматическая проверка наличия цитаты не доказывает правильности интерпретации. Сгенерированные метки не называются ручными.

Коммерческие API включаются только при предоставленном доступе и бюджете; отсутствие такого сравнения явно отмечается. Нельзя объявить SotA только потому, что выбран новый split; бонусы и допуск темы решает преподаватель.

## Журнал уточнений

- После измерения ресурса и до получения эмбеддингов: объединение 1024-мерных эмбеддингов с таблицей реализовано как Ridge на cross-fitted остатках вместо высокоразмерного CatBoost. Это обеспечивает одинаковую схему объединения с TF-IDF. Генеративный бюджет уточнён под JSON с цитатами (256 токенов).
- Непрерывная разработка не является зарегистрированным независимым preregistration: метрики первых методов уже доступны при реализации последующих. Все изменения фиксируются здесь; параметры новых текстовых методов выбираются только по dev. Это ограничение нужно учитывать при интерпретации значимости и новизны.
- При аудите первого zero-shot запроса обнаружена почти полная абстенция. На 32 train примерах проверен более короткий англоязычный запрос с двумя положительными разобранными отрывками из train ID 7929104599/7866165689. Примеры подготовлены ассистентом из имеющихся данных; это не независимая ручная разметка. V1 сохраняется целиком; V2 оценивается отдельно на той же фиксированной подвыборке. Это исследовательская итерация после доступности части результатов, не чистый независимый confirmatory test.
- Добавлены диагностические контроли без настройки по test: среднее цен тех же трёх соседей, что используются в 3-shot LLM, и residual-текст поверх расширенной таблицы. Последний использует отдельный 3-fold group OOF для расширенного CatBoost и вес остатка 0..1 с шагом .05 по dev. Все прежние результаты остаются в таблице. Это уточнение проверки инкрементальной ценности текста, а не ранее заявленный эксперимент.
